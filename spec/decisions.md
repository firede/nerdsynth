# NerdSynth 决定记录

> 已定的写成结论，附理由和日期。尚未确认的标「提议」。

## 质量目标（2026-10-29）

- **目标是可信的音色和 MIDI 播放正确，不可信的输入不崩溃、不出 NaN、不 panic、渲染路径不分配**。工作预算是尽力而为的保护：病态的文件和事件流会拖拍而不是卡住音频，但不对任意输入保证单次操作耗时的严格上界（单个事件整个生效；代价单位按开发机定；高复音时 NoteOn 要扫全部声部槽）。经过五轮独立审查后定下，不再为对抗输入下的实时保证增加结构性的复杂度。

## 代码来源与许可（2026-10-29）

- **混响和合唱重写，不再移植 FluidSynth。** 原先的 `effects/reverb.rs`、`chorus.rs` 逐个函数移植自 FluidSynth 2.6.1 的 `fluid_rev_fdn.cpp`、`fluid_chorus.c`，FluidSynth 是 LGPL-2.1，逐行翻译算衍生作品，不能以 `MIT OR Apache-2.0` 发布。0.1.0 前删掉，由没看过 FluidSynth 源码的实现者按公开的算法重写（混响先基于公有领域的 Freeverb，后按指标换成 Jot FDN（公开的论文方法），合唱是通用的调制延迟），只用 FluidSynth 文档里的参数默认值和渲染结果（黑盒）做对照。代价：效果不再与 FluidSynth 逐位一致，差分测试的 fx 用例按原阈值判定，5 个都通过（`fx/gu/quiet-send` 的左右平衡余量最小，2.23 / 3.7：音符在文件开头，合唱和干声的相位干涉取决于 LFO 初相，三个声部放哪边是按它选的）。
- **其余参照 FluidSynth 的地方是照行为实现**：单位换算、曲线、声像、包络、LFO、滤波（RBJ cookbook）、调制器的取值，都按规范和公式重新写，注释里的 FluidSynth 函数名只标出行为的出处。以后参照 FluidSynth 时也只照行为和公式，不翻译它的代码。

## 效果器的质量目标（2026-10-29）

- **混响、合唱在质量指标上不输 FluidSynth，性格指标接近它。** 指标和容差在 `tools/fxmetrics/README.md`。质量指标（混合时间、后期回声密度、尾音频谱粗糙度、96 个音的尾音电平离散度和高点、衰减平滑度、IACC、合唱带外 SNR、结尾截断电平）在 44.1k、48k 判定，22.05k、96k 抽查；性格指标（各频带 T30、EDT、起音、湿声电平、重心、合唱速率和深度）只在 44.1k、48k 判定：FluidSynth 的混响延迟按帧固定，换采样率就是另一台混响。另有「音尾谱宽」防止用深调制刷着色指标（深调制会让尾巴听起来像合唱）。
- **结果**：44.1k、48k、96k 全部通过。混响从 Freeverb 换成 8 线 FDN 才过：Freeverb 的尾音粗糙度（3.55 dB 对 FS 1.86）、离散度、IACC、重心、起音都不过；FDN 后混合时间 219 ms（FS 461）、粗糙度 1.64 dB、IACC 0.05（FS 0.17）。代价：混响 21 → 42 ns/帧，内存 44.1k 下 200 → 381 KiB，约单核 0.2 %。
- **已知例外**：22.05k 抽查的「音尾高点」4.37 dB 对 FS 3.47（限 FS+0.5）。FS 在 22.05k 下延迟时间翻倍、模态密度也翻倍，它自己这一项随采样率在 3.47–5.90 dB 间变；我们的设计与采样率无关，各采样率 4.2–4.4。稳过要 16 条线或更长的线，开销和内存再翻倍，只为一个抽查采样率，不做；也不挑一组凑巧能过的调制初相。所以 `mise run fx-metrics` 目前以这一项失败退出。
- **合唱不学 FluidSynth 的反相**：FS 的合唱左右 lag 0 相关 −0.94，单声道下湿声约 −15 dB；我们的是 +0.41。

## 结构化的错误（2026-10-29）

- `Error` 的变体带结构化的内容，而不是字符串：宿主能分辨「文件坏了」（`Invalid`，带格式）、「文件没坏但不支持」（`Unsupported`，可以提示用户换 SF2 或转成 format 1）、「设置越界」（`Config`，指出哪个设置）。坏文件的具体原因只给人看，不做成枚举：解析的检查有几十处，会随实现变，列成接口只会锁死实现。0.1.0 之前改，之后改就是破坏性变更。

## 定位与语言（2026-10-28）

- 用 Rust 重新设计、实现 SoundFont 合成器，不再在 go-meltysynth 的 fork 上修补。理由：
  - 实时安全：没有 GC，可以保证渲染路径不分配内存。
  - DSP 性能：LLVM 自动向量化，可以做 SIMD。
  - 采纳面：C ABI 可以服务任何语言，也能做 DAW 插件。
  - 现有的 Rust 库各有缺口：rustysynth 没有调制器，OxiSynth 停在 0.1，xsynth 只做 SF2 的子集。
- go-meltysynth 上的工作（解析的防御、fuzz 发现的问题、两轮审查的清单）作为需求和测试的来源，记在 `behavior.md`。
- 公开的文档（README、rustdoc）用英文，面向使用者。开发文档（spec/）和提交信息用中文。
- 许可证 `MIT OR Apache-2.0`，Rust 生态的惯例，便于被采用。
- `rust-version = "1.85"`：edition 2024 的最低版本。不追新，方便被依赖。

## 行为的出处（2026-10-28）

- 规范写明的照 SoundFont 2.04；规范没写的照 FluidSynth 2.6（差分测试台用 brew 装的 2.6.1，混响用 `synth.reverb.engine=fdn`，即 2.4 以前的默认混响），它是使用最广的参照，也是差分测试的主对照；偏离两者的地方逐条记在这里。FluidSynth 的事件按 64 帧的块量化并晚一块生效，NerdSynth 按帧生效；测试台让各家在同一帧收到事件，见 `tools/diff/README.md`。
- initialAttenuation 的生成器值乘 0.4。FluidSynth 和 SpessaSynth 都这样做，大多数 SF2 也是照这个响度调的。调制器的输出不乘。

## SF2 解析（2026-10-29）

- **默认调制器有两处偏离规范的印刷：**
  - CC10 → pan 的量用 500，不是规范写的 1000。来源是双极性的，1000 会让 CC10=32 就已经全左；500 正好让 CC10 0–127 覆盖整个声像范围，FluidSynth 也是 500。
  - CC7 的来源用 0x0587。规范把它印成 0x0582，但描述写的是 index 7。
- **弯音调制器的目标用 fineTune**（同 FluidSynth）。规范说的 "initial pitch" 没有对应的生成器。
- **放宽的地方**（规范要求拒收，实际的文件常有这些问题）：
  - 终止记录的下标只检查不越界，不要求正好等于块的大小。
  - 有 ROM 采样但没有 irom 时不拒收；用到 ROM 采样的区不发声。
  - RIFF 的大小声明得比文件长时，只要文件正好结束在块与块之间，照常加载。
  - 文本按 UTF-8 解码，失败时改用 Latin-1。
- **严格的地方：**
  - 缺 ifil，或 pdta 的九个子块缺任何一个，报 Invalid；同一个块出现两次也报 Invalid。
  - 无效的调制器在加载时丢弃（§8.2.1）。CC33–63 照 FluidSynth 当作独立的控制器保留。
- **区的划分：** 第一个 sampleID（preset 区是 instrument）生成器结束这个区，其后的生成器忽略（同 FluidSynth）。规范里"最后一个生成器"和"其后的忽略"两种说法互相矛盾。
- **keyRange、velRange 的位置规则也适用于全局区。** 全局区的范围会合并进其他区，每个区取两级范围的交集。
- **上界：**
  - 全文件的 (preset 区, instrument 区) 对不超过 2^20 个。GeneralUser GS 约 2.3 万个。
  - 合并后所有区的调制器总数不超过 2^22 个。
  - 如果以后遇到超过这个上界的正规大音色库，改成按每个 preset 计。
- **链接调制器：** 加载时保留，但全局区合并之后，它们的相对下标就失效了，第二阶段重新设计存储方式。

## Sequencer（2026-10-29）

- 短于 1 ms 的循环不播：标记之间太近时，改为循环整曲；整曲也短于 1 ms 时只播一次。这样循环长度为 0 时不会死循环，每次调用的工作量也和请求的帧数成正比。
- `seek` 和回卷一样先释放文件用到的通道上的音，否则跳转之前在响的音会一直挂着。
- `Sequencer::render` 分段渲染：先把事件排进 synth 的队列直到排满，渲染到第一个没排进去的事件那一帧，再接着排。不分配内存；事件只在 synth 的工作预算用完时迟到（见「引擎」），或者队列被别人排的、更晚的事件占满时。
- **synth 没经过 Sequencer 渲染的帧算作音乐暂停**（第三轮审查）：每次 `render` 按 synth 的当前帧重新对齐，音乐从上次停下的地方接着走。之前只在第一次 render 时记下起点，宿主暂停音乐但 synth 继续渲染（放音效、等尾音）之后，所有事件都落在缓冲区开头，节奏量化成缓冲长度。
- **`Sequencer` 的 `Clone` 保留待交出队列的容量**：宿主常在别的线程建好再交给音频线程，派生的 `Clone` 只按长度分配，克隆在音频线程上会分配内存。

## Sequencer 的跳转（2026-10-29）

- **跳转时先复位文件用到的通道**（见下文「只碰文件用到的通道」）。只发 CC64/66=0、CC123、CC121 不够：按 RP-015，CC121 不重置音量、声像、效果深度、bank、program、弯音范围等，而追溯只交出目标之前文件设过的值。反例：0 s 一个音，1 s 处 CC7=10、CC10=0，整曲循环，第二圈起音量和声像都没复原；`seek(0)` 同样。
  - 复位是 crate 内部的队列项（`synth::queue::Queued::ResetChannels(方式, 通道掩码)`），由 `Sequencer::render` 排进队列，在跳转那一帧生效：掩码里的每个通道 `reset` 加 program 0（同 `Synth::reset` 对通道的处理），不停声部，不清效果。公开的 `Event` 不加变体，因为没有哪条 MIDI 消息有这个语义。
  - 代价：`next_events` 交不出这个复位，只交出文件里的复位消息（如果有）。完整的跳转只有经过 `render` 才有。另一种做法是把复位展开成一串 MIDI 事件（CC7=100、CC10=64、bank 0 加 program 0、RPN 0=2 半音……），但鼓通道、GM2 的 bank 状态没法用通道消息精确恢复，所以没这样做。
- **复位也恢复 bank select 方式**（GS/GM/GM2），不只是通道。取目标之前文件里最后一条复位消息设的方式；没有就取起始方式：`Sequencer::new(smf, &synth)` 时 synth 的方式，`with_sample_rate` 时是 GS（同新建的 `Synth`）。只复位通道而不管方式的话，目标之后才出现的 GM System On 会在跳回去后仍然有效（CC0 被忽略），和从头播不一样。
- **文件里的复位消息在跳转时不重发**，换成上面的内部复位（方式取那条消息的）。重发的话，每圈循环都会停掉所有声部（释音尾巴被切断）、清空混响和合唱的延迟线。通道状态两者相同。
- **跳转目标那个 tick 上的复位消息也并入内部复位。**（审查后，2026-10-29）最常见的文件是 tick 0 一条 GS/GM 复位、整曲循环（或循环起点就在那里），这条复位属于循环体本身；原先回卷后照样执行它的 `system_reset`，上一条的目的落空（反例：tick 0 GS 复位、0–0.5 s 一个释音 2 s 的音、整曲 1 s 循环，回卷后 316 帧声部从 2 掉到 1，没有复位的文件仍是 2）。
  - 做法：回卷和 seek 的目标 tick 上若有复位消息，追溯一直做到其中最后一条（含），从它之后接着播（`chase::resume_at`）；回卷的接续位置在 `Sequencer` 创建时算好，回卷仍不分配。
  - 同 tick 上复位之前的事件：被那条复位撤销（通道状态清掉，音被 `system_reset` 停掉），跳转后不再交出。和从头播的差别只是从头播时那些音会响约 2 ms 再淡出，跳转后不响。复位之前的「对 synth 无效」的 sysex 也随之丢掉（与追溯里复位之前的 sysex 一样）。
  - 同 tick 上有几条复位：取最后一条，方式也取它的。复位之后的同 tick 事件照常播放，其中没有复位。
  - 只看目标那个 tick：之后 tick 上的复位是循环体里真正的事件，照常执行。第一圈从头播放时，tick 0 的复位照常执行。
  - `next_events` 交出的是那条复位消息加它之后的事件，宿主自己的 synth 执行这条消息，等于原来回卷后它执行的那条，只是少了被它撤销的事件。
- **跳转只碰文件用到的通道。**（审查后，2026-10-29）宿主常用同一个 synth 同时放 BGM 和实时输入、音效（游戏里常见）；原先每次回卷或 seek 都对 16 个通道发 CC64/66=0、CC123、CC121 并复位，松掉其他通道的音，复位它们的音量、program 等。
  - 解析时记下文件用到的通道掩码（`Smf::channels`，不公开）：有任何通道消息（含音符）的通道，加上 GS rhythm part 指向的通道（它改那个通道的鼓、bank、program）。循环标记的 CC 已从事件里拿掉，不算。掩码按整个文件算，不按目标之前：目标之后才用到的通道，从头播到目标时也是初始状态，复位它们才对。
  - 释放和内部复位都只作用于掩码里的通道；追溯本来就只给文件改过的通道交出事件。
  - 并入内部复位的文件复位消息（上一条）也只复位掩码里的通道，虽然从头播时它复位了所有 16 个通道。取舍：「像从头播到这里一样」是对文件的内容而言，文件没用到的通道不影响文件播出来的东西；而如果按消息本身复位全部通道，tick 0 有复位的循环每圈都会复位宿主的通道，正是这一条要避免的。第一圈从头播时，文件里的复位消息照常作用于所有通道、停掉所有声部，这是文件自己的行为，不改；宿主应在它之后再设自己的通道。
  - 没法限定到通道的：bank select 方式是 synth 全局的，内部复位照旧把它设成目标处文件的方式，宿主通道上的 CC0/CC32 也随之按这个方式解释。不恢复方式的话文件自己就播不对（见上文「复位也恢复 bank select 方式」）。
  - 文件中途的复位消息（不在目标 tick 上）在正常播放时照常作用于所有通道，跳转追溯到它之后也只复位掩码里的通道，规则一致：跳转从不改动文件没用到的通道。
- **追溯（`midi/chase.rs`）照 Synth 的语义做，并保证顺序等价：**
  - 每个通道的状态用 synth 自己的 `Channel` 镜像，CC121 调用同一个 `init_controllers(true)`（同一张 RP-015 保留表），sysex 用同一个 `classify_sysex` 判定（XG System On、GM System Off 不是复位，GS「exit GS」是；rhythm part 只在 GS 方式下有效）。
  - 结构性事件（bank select、program、CC 6/38/98–101、CC121、rhythm part）按原顺序记下，每条附带它当时读、写了哪些状态格（寄存器、bank、drum、program、弯音范围、调制深度、每个生成器偏移等）；交出前从后往前做活跃性分析，去掉写的格在被读到之前都被覆盖的事件。所以 SoundFont NRPN 的 LSB 仍在 MSB 之前（旧版先发 MSB，CC98 清掉的 cc[38] 让低 7 位丢失：NRPN 120/52 data=8292，从头播 467.2 Hz，seek 后 441.0 Hz），rhythm part 之前的 program 不会在它之后重新生效，CC121 之前设的 CC2、CC4 也不会被重发。
  - 其余状态（普通 CC、弯音、通道触后、复音触后）在结构性事件之后，按与它们回放后的状态之差补发。复音触后现在也追溯（synth 保存它，新音会读到）。
  - 对 synth 不起作用的 sysex 仍按顺序在最前面重发，给其他宿主。
  - debug 构建里，追溯交出前会把剪枝后的事件在新的 `Channel` 上回放一遍，断言得到同样的状态。
  - 局限：镜像的逻辑是 `Synth::control_change`、`data_entry` 的副本，没有把 synth 的代码改成两边共用。一致性靠随机文件的对比测试（从头播 vs `seek`、第一圈 vs 之后几圈，比较 synth 的通道快照）。改 synth 的这几个函数时要同步改 `chase.rs`。
  - 状态的长度：一般受状态格的数目约束；只有在 CC99=120 之后连续很多个 CC98（累加 SoundFont NRPN 编号）这种病态输入下，或者文件里有很多条 synth 不认的 sysex（照样交出，给别的合成器用）时，才会随事件数增长。交出它们的工作受 synth 的工作预算约束（见「引擎」）。
- **`Sequencer` 的采样率与 synth 关联。**（0.x，公开 API 改了。）
  - `Sequencer::new(Arc<Smf>, &Synth)` 取 synth 的采样率和起始 bank select 方式；`Sequencer::with_sample_rate(Arc<Smf>, u32) -> Result<_, Error>` 给不经过 `Synth` 的宿主，采样率范围同 `Config`（8000–192000），否则报 `Error::Config`。旧版接受任意值（0 当 1），而「短于 1 ms 不循环」以秒计，极低采样率下每帧可能回卷很多圈；现在一圈至少 8 帧。
  - `render` 遇到采样率不同的 synth 时，从已播到的时间起改按 synth 的采样率换算（`sample_rate()` 随之改变），而不是悄悄放错速度。
- **`seek` 会分配内存，耗时与目标之前的事件数成正比**，rustdoc 写明不要在音频线程上调用。追溯要在内存里记状态，改成不分配不划算。回卷不分配：循环起点的状态在 `Sequencer` 创建时算好，`pending` 预留了容量。

## 引擎（2026-10-29）

- **停掉一个音的三种方式分开处理：**
  - exclusive class 照 FluidSynth（`fluid_voice_kill_excl`）：把旧音的 volEnvRelease 改成 -2000 tc（约 315 ms），调制器和 NRPN 偏移照常叠加，然后不管踏板直接释音；调制包络用它原来的释音时间。已经在释音的音也会被截停，从当前电平按新速率继续衰减（FluidSynth 释音后声部仍算在发声）。镲片之类的打击乐要这段尾音，2 ms 淡出听起来是被掐断的。
  - 抢占和 All Sound Off 用 2 ms 淡出。FluidSynth 抢占时直接硬切；我们淡出是为了不出咔哒声。差分测试 `polyphony/gu/organ-8voices` 的包络相关性因此略低于阈值（0.9965），这是有意的。
  - 被 exclusive class 截停的音状态记为已释音，抢占时优先被拿走。FluidSynth 里它仍算按着的音。只在复音数用满时才有差别。
- **段按声部各自维护**（审查后，2026-10-29）：原先任何事件都切开全局的段，所有声部都要重算控制量，每帧一个事件时 256 复音掉到实时以下；Sequencer 只排程到本次 render 的末尾，渲染调用的边界也会切段，输出随缓冲大小变化（差约 1e-3）。现在只有被事件改动的声部重新开段：同通道的状态变了（`Channel::version`、复音触后），或者声部被释音、淡出、截停。差分测试结果不变。
- **一次 NoteOn 最多起 `max_voices` 个声部**，多出的区域不发声。FluidSynth 不封顶，但多出的区域只会抢走本音前面区域的声部。空闲槽、抢占候选（按优先级排序）、可腾出的淡出声部，都在需要时才整理一次，存进预分配的数组。之前每个区域都要扫几遍全部声部，一个 25 KB 的恶意 SF2（一个音约 100 万个区域）能让一次 NoteOn 卡 2 s 到 48 s；现在是 0.5 ms 到 7 ms。
- **NoteOn 的有界性，第二轮审查补的三处**（2026-10-29）：
  - **每个区合并后最多保留 64 条调制器**（加载时截断），正是一个声部的 `ModList` 能放下的数量。instrument 区的调制器先放进 `ModList`，多出的本来就不会播，结果不变；preset 区超过 64 条时，多出的不再参与合并（之前它们若与 instrument 区的某条相同，会加到那条的量上）。之前每条 preset 调制器都要在 64 项里线性查找，一个 600 KB 的 SF2（preset 区 6 万条调制器）让一次 NoteOn 卡 342 ms（4096 声部时 5.4 s），现在是 0.5 ms（5.4 ms）。截断的调制器不计入 `ModList::dropped()`。
  - **采样没东西可播的区域不进 `regions()`**：加载时给每个 instrument 区算好（采样在数据里至少 2 个点、不在 ROM，加上偏移生成器后的位置仍能播）。偏移生成器只能在 instrument 层设置，未经调制时在加载时就定了；调制器改动偏移的情况仍由声部开始时检查。之前空采样的区域也会先抢一个声部再失败，100 万个这样的区域让一次 NoteOn 卡 100 ms，还白白停掉一个在响的音；第二轮改成 NoteOn 时逐区检查后是 0.5 ms，但带偏移的区域每个都要算一遍生成器之和，100 万个仍要 72 ms（第三轮审查）；现在全在加载时算，0.35 ms。
  - **每个音的第一个受害者线性扫描找出**，同一个音要抢第二个时才排序。复音满时每次 NoteOn 从 6.7 µs 降到 3.1 µs（256 声部）。
- **scaleTuning 叠加后钳制到 0–1200**（E-03），与其他生成器一致。FluidSynth 直接用未钳制的 `gen[GEN_SCALETUNE].val`（`fluid_voice_calculate_pitch`），instrument 100 加 preset 2000 时每键 2100 音分。
- **持续音踏板（CC66）只在从抬起变为踩下时锁定当时在响的音**；踩着时再收到 ≥64 的值不重新锁定。FluidSynth 每收到一次 ≥64 都重新锁定，会把踏板踩下期间新起的音也持住，与 MIDI 对持续音踏板的定义不符。
- **`find_preset` 用加载时排好序的 (bank, program) 表二分查找**，重复的 preset 仍取文件里的第一个（§7.2）。
- **MSRV 1.85 实测编译**：`mise run msrv`（`cargo +1.85.0 check -p nerdsynth --all-targets --features testkit`）。唯一一处 let chain（1.88 才稳定）已改写。
- **exclusive class 在一个音的所有区域都起好之后，统一截停一次。** FluidSynth 在每个区域开始时截停，但截停不改变它算的抢占优先级，所以结果相同。
- **exclusive class 只停同一通道、同一 preset 的旧音**（规范 §8.1.3）。FluidSynth 只看通道（`fluid_synth.c:5460`），换了 preset 之后，同类号的旧音也会被它停掉。
- **ct2hz、cb2amp 用精确值。** FluidSynth 查表，截到整音分、整 cB。
- **包络和控制量的时间：**
  - 包络逐帧推进；各段长度照 FluidSynth 以 64 帧的块计，音的起止与它对齐。
  - 控制量（包络、LFO、调制器、滤波器的目标截止频率）每段（64 帧，事件处切开）求一次，取段末的值，增益在段内线性过渡。
  - **滤波器照 FluidSynth 2.6 逐帧滑动截止频率**（第二轮审查，2026-10-29）：原先在段内线性插值系数，并以为「稳定二阶节的凸组合是稳定的」，但时变系统不是这样：Q 高、调制快而深时输出可达 1e34（状态有限，NaN 保护拦不住）。现在截止频率按音分滑向目标（64 帧乘 clamp(Q, 1, 5)），Q 在 64 帧内滑动，滑动期间每帧用 1 音分一项的 sin/cos 表（f32，同 FluidSynth）重算系数。审查给的几组参数与 FluidSynth 的峰值相差在 2 倍以内。另加保险：一段输出的峰值超过 1e5（96 dB 共振约放大 250 倍，满幅输入到不了），或状态不是有限值，就停掉声部。第二轮原先查的是状态（超过 1e7），但 Direct Form II 的状态在共振处约放大 Q/sin²(ω/2) 倍，低截止、高采样率时合法的共振也会过 1e8，第三轮审查发现 192 kHz、Q 400 dB 的声部被掐掉，FluidSynth 照常发声，因此改查输出。截止频率因此按整音分取表，与「ct2hz 用精确值」那条不同，这里照 FluidSynth。
  - 默认 1 ms 的 delay 照 FluidSynth 取整到块：65.5 kHz 以下为 0，96 kHz 以上是 64 帧。规范字面上是 1 ms。
- **最短音长照 FluidSynth，默认 10 ms**（第三轮审查，2026-10-29）：`Config::min_note_length`（0–1 s）。早于它的释音（NoteOff、踏板抬起、exclusive class 截停）先把声部标为已释音（抢占、踏板逻辑立即生效），包络到声部开始后满 `min_note_length` 的那一帧才进入释音（从声部开始算，含 delayVolEnv，同 FluidSynth `fluid_rvoice_noteoff_LOCAL`；delay 不短于它的音，同一帧的 NoteOn+NoteOff 仍然无声）；段在那一帧切开，帧精确（FluidSynth 按 64 帧的块检查）。原先不实现：同一帧的 NoteOn+NoteOff（转换来的 MIDI 鼓轨常见）完全无声。差分测试结果不变（FluidSynth 默认就是 10 ms）。抢占和 All Sound Off 的淡出不受影响。
- **不实现** CC8 custom balance。
- **同一通道上重复的同一个音，旧音照常 NoteOff**（踏板照样保持），鼓通道也一样。同 FluidSynth 的默认（`synth.note-cut=0`，`fluid_synth_release_voice_on_same_note_LOCAL`）；它的 note-cut 1/2 会在鼓通道或所有通道上直接停掉旧音，不符合 SF2，不做。
- **SF2 加载时，合并好的全局区调制器先截到 64 条再逐区复制**（第四轮审查）。原先每个区都复制一份完整的合并表（最多约 6.5 万条）再截断，1.17 MB 的文件加载 45.7 s，现在 74 ms。结果不变：区的调制器原位替换或追加在后面，前 64 条只来自全局表的前 64 条或追加项。
- **`is_silent` 在有到期事件等预算时为假**；队列里更晚的事件不算（文档写明）。`render_interleaved` 的奇数长度缓冲，最后一个样本清零。
- **`Config::gain`，默认 1**（第三轮审查）：输出乘以它，在非有限值兜底之前。默认电平等于 FluidSynth gain=1（差分测试台这样比），是 FluidSynth 默认 0.2 的 5 倍；保持 1 是因为它就是声部增益的自然刻度，改默认会让所有电平测试失去「0.5 的直流采样输出 0.5×滤波增益×声像」这个直观关系。rustdoc 写明完整的 GM 编曲会远超满幅。
- **事件的工作预算**（第三轮审查，2026-10-29）：审查用对抗输入证实，单次 render 的工作没有可用的上界：队列塞满 4096 个「每音 256 区域、每区 64 条调制器」的 NoteOn，64 帧要 2.1 s；Sequencer 在 tick 0 有 30 万个 CC 时 25 ms；1 ms 的循环里 2 万个 CC 持续慢于实时（1.19 s/s）。现在事件从按帧补充的预算里扣工作，用完就顺延（见 design.md「工作预算」）。同样的输入：NoteOn 洪泛的最坏单次 render 1.7 ms（一个 NoteOn 本身约 1 ms，加突发），1 s 音频的 CPU 约 190 ms（大半是 512 个声部本身的渲染）；30 万 CC 一次 render 0.32 ms；1 ms 循环 80 ms/s；4096 个 GS 复位 19 ms → 0.17 ms。代价的单位按本机实测定（普通事件约 60 ns，每个声部槽 1–9 ns，区域对 2–4 ns，起一个声部 2.5 µs 起、每条调制器约 32 ns，切段每声部 0.26–0.58 µs），宁高勿低。取舍：
  - 病态的文件和事件流会拖拍，而不是卡住音频；正常的音乐远在预算之内（256 个音同一帧准时，差分测试结果不变）。
  - 不提供配置项：代价单位是实现细节，公开出去就锁死了。慢的机器上「四分之一」会变成更大的比例。
  - 一个事件总是整个生效，所以单个 NoteOn 的代价（遍历区域对加起 `max_voices` 个声部，4096 复音时可达十几毫秒）不受预算约束，只是之后的事件等得更久。
  - 不在 Sequencer 里另设预算：它往队列里排的事件最终都要 synth 处理，受 synth 的预算约束；它每次调用多做的工作受队列容量约束。
  - 第四轮审查修了三处（2026-10-29）：
    - **队列满时的 `send` 只处理最老的一个到期事件**。原先处理全部到期事件，不管预算：Sequencer 把队列排满后，宿主一次 `send` 卡 311 ms。现在 125 ns；Sequencer 也只排到剩八分之一，宿主的 `schedule` 平时不会被挤得 `QueueFull`。
    - **等预算的事件只在 64 帧的网格上放行**。原先把块切到预算回正的那一帧，这一块结束时又扣块费（64 + 4×槽数）；48 kHz 默认配置下块费 2112 比一帧挣的 2083 还多，吞吐掉到每秒 1.5k 个事件，积压一直涨。现在等着的事件最多再晚 63 帧，吞吐回到预算的速率（各采样率、4096 复音下 6 万个 CC 都在 20 ms 音频内放完）。为了与 render 的调用长度无关，Synth 记着「在等」：等着时调用边界上不放行。
    - **只有扫声部槽的事件按槽数计价**。原先每个事件都加槽数，4096 复音时一个 CC 估 8256、实际约 5 ns。
  - 第五轮审查后（2026-10-29）：
    - **预算份额从十分之一提到四分之一**：GeneralUser、256 复音、16 通道各 1 kHz 弯音时，十分之一下 69% 的块结束时还有事件在等，而 CPU 只用了 21%。份额不公开（理由同代价单位）。
    - **预算吃紧时输出也与 render 的调用长度无关**：审查发现两个成因（切段费在决定块的终点之后才扣；越过未来事件时没记「在等」），密集事件下 117 组里 79 组输出不同。现在切段费攒到网格再扣、越过时记「在等」。
    - **exclusive class 截停计入预算**（每声部同切段），原先少计约 22 倍。
    - **Sequencer 在队列被宿主的未来事件占满时不再逐帧渲染**，直接渲到那个事件或网格帧。
    - `Config::gain` 限 0–1000：更大的值会让输出溢出，被非有限值兜底清成静音。
    - 不做：`try_send`（队列满时 `send` 仍强制做一个事件，单次有界；宿主转发不可信事件流时要自己限流）；活跃声部表。
- **复位与 sysex：** GM、GS 复位清空混响和合唱的延迟线，LFO 不复位（同 FluidSynth）。延迟线已经静音（低于阈值，渲染时也跳过处理）时不清，复位的代价因此不随效果器的大小增长。sysex 的 device id 接受 0x10 和 0x7F（广播）。
- **效果：** 输入的非有限值当 0，过大的值钳制；状态一旦出现非有限值就复位。绝对值小于 1e-30 的输入当 0，状态不会变成次正规数。混响、合唱参数现在固定，没有公开 API。
- **力度→滤波截止默认关**（`VelocityToFilter::Off`）。FluidSynth 2.4–2.6 定义了这条默认调制器（带力度开关），实际求值却是 0（`fluid_mod.c:450–483`），文件里与它相同的调制器也一样；SpessaSynth 没有这一条。另提供 `Switched`（FluidSynth 的定义）和 `Linear`（规范 2.01 的线性 -2400 音分）。
- **CC74 → 截止频率默认关。** 规范和 FluidSynth 都没有这一条；`cc74_to_filter = true` 时照 SpessaSynth 的默认调制器（±9600 音分）。

## 公开接口（2026-10-29）

发布前收敛接口面：以后加东西（新字段、新变体、新的内部表示）不该破坏兼容。

- **数据模型字段私有，只给访问方法**（`Info`、`Preset`、`Instrument`、`Sample`、`Modulator`、`Source`）。只加 `#[non_exhaustive]` 也能挡住外部构造，但字段的类型和存法仍是契约；链接调制器第二阶段要重新设计存储，SF3 可能给 `Sample` 加东西，访问方法让这些改动不外泄。这些类型外部本来也不需要构造：没有公开接口接收它们。
- **`Region::generators() -> [i32; 61]` 改为 `Region::generator(GeneratorType) -> i32`。** 数组把生成器的个数和按编号的存法写进了契约；按类型取值只依赖规范的编号。加了 `GeneratorType::from_number(u16)`，用来遍历全部生成器，或把调制器的目的地（编号）换成类型。引擎内部仍用 `pub(crate)` 的整组数组。
- **`ModList` 保留为不透明类型**，只公开 `new()`、`as_slice()`、`dropped()`。`Region::modulators` 要做到不分配，就得由调用方提供定长的表；容量（64）、`push`、`clear` 是内部的，降为 `pub(crate)`。`dropped()` 留着：它如实告诉调用方有调制器没放下（也就不会被播放）。
- **`DEFAULT_MODULATORS` 不公开。** 实际生效的默认调制器还取决于 `Config`（`velocity_to_filter`、`cc74_to_filter`），单独公开这张表会误导；以后改动也不该算破坏兼容。测试经 `testkit::sf2::DEFAULT_MODULATORS` 拿。
- **`GENERATOR_COUNT`、`generator_range` 不公开**：只对数组形式的生成器有意义，`generator()` 返回的已经是钳制后的值。
- **`#[non_exhaustive]`：**
  - `Event`：以后可能加系统实时消息、XG 等。变体本身不加，外部仍能用 `Event::NoteOn { .. }` 构造。
  - `Interpolation`：可能加 FluidSynth 的 7 点 sinc 等。
  - `VelocityToFilter`：其他实现的形式可能再加。
  - `LoopMarkers`：游戏的循环标记约定不止这几种（比如 meta 文本标记）。
  - `SampleKind`：SF3 和以后的采样类型。
  - `Error` 已经是；`Config` 已经是（结构体，用 `Config::new` 再改字段）。
  - **`GeneratorType` 不加**：它就是规范的 0–60 号，SoundFont 2.04 是最后一版；文件里的其他编号在加载时丢弃，不会成为变体。保持穷尽，`match` 不必写 `_`。
  - **`QueueFull` 不加**：它只是一个信号；被拒的 `Event` 是 `Copy`，调用方手里还有，容量在 `Config::event_capacity`。加了反而不能写 `Err(QueueFull)`。
- **`SysEx::CAPACITY` 保持公开**，文档写明以后只升不降。宿主需要知道多长的消息会被 `SysEx::new` 拒绝；调大不破坏使用它的代码。
- **`Debug`：** `SoundFont`、`Smf` 原来派生 `Debug`，`{:?}` 会打出数 MB 的采样或整份事件列表；改为手写的摘要。`Synth` 原来没有 `Debug`，宿主的结构体派生 `Debug` 会受阻；`Sequencer` 原来派生，会带出 `Smf` 和待交出的事件。三者都改为摘要。`SysEx` 只打出有效的字节，`ModList` 只打出已有的调制器。
- **`testkit` 不属于公开契约**（`#[doc(hidden)]`，特性 `testkit`）：测试和 fuzz 要的构造方法（`raw_source`、`raw_modulator`、`DEFAULT_MODULATORS`）放在这里，不给数据模型加公开的构造函数。
